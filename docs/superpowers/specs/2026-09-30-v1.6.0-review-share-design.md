# 设计：v1.6.0——回顾与分享（时间线 / 周报图片 / 时薪模式）

日期：2026-09-30
状态：实施中（用户拍板按推荐方向开发并发布）
前置：1.5.1 已发布（发布链云端化）；二期模块化完成（命令可住任何模块、capabilities 自动补齐）

## 0. 定位与范围

1.1–1.5 把记账 / 洞察 / 守护 / 更新 / 备份铺满，1.5.1 完成工程底座。1.6.0 主题定为**回顾与分享**——把已有数据"用出去"，三个特性：

1. **「这一天怎么过的」时间线回顾**：洞察区新增「时间线」tab，逐小时呈现前台构成（四类分类秒）+ 键鼠事件 + 媒体 + 该小时最常用应用，支持按日回翻；
2. **周报 / 月报一张图**：账单页一键把当前周期账单画成 PNG（canvas 手绘），保存到下载目录或复制到剪贴板；
3. **时薪 / 日结计薪模式**：计薪方式新增 "hourly"——直接按时薪 × 工时计薪，覆盖时薪工 / 日结工 / 兼职人群。

明确不做（记录否决理由）：跨平台（Win32 耦合过深）、数据云同步（违背本地数据主权定位）、更多提醒类型（避免骚扰化）。

## 1. 决策表

| 决策点 | 结论 | 理由 |
|---|---|---|
| 时间线数据源 | app_usage_hourly（按小时×应用秒，查询时归类）+ act_hourly（EVENTS_EXPR）+ audio_usage_hourly | 三表同构 (date,hour)；分类口径沿用查询时归类，改分类即重算历史 |
| 时间线颗粒 | 小时 × 全 24 行（空小时全 0） | 监控粒度的天然上限；行数固定渲染简单 |
| 「离开」表达 | **不臆造**：无前台+无键鼠+无音频的小时 = 无记录空条 | 监控关闭 ≠ 离开；延续「断线不画 0」的诚实数据原则 |
| 时间线导航 | `offset`：0=今天，正数往过去翻，未来封顶 | 与账单 offset 语义同向；未来日无数据 |
| 图片生成 | 前端 canvas 手绘（2x 密度），数据源 = billData 缓存 | 无打包链可引 html2canvas；DOM 截图方案复杂度高，专用卡片排版更可控 |
| 图片保存通道 | 新命令 `export_image(filename, content_base64)` 复用 export_csv 的清洗+下载目录逻辑（抽 `safe_download_path` 助手） | `<a download>` 在 Tauri WebView 被取消（export_csv 注释已论证），必须后端写盘 |
| 剪贴板 | ClipboardItem 探测可用则复制 PNG，失败 toast 降级为仅保存 | WebView2 基于 Chromium 支持；降级路径必须存在 |
| 时薪模式配置 | `salary_mode`（"monthly" 默认 / "hourly"）+ `hourly_wage`（f64 默认 0） | serde default 零迁移；merge 无 schema 零登记 |
| 时薪口径 | 抽 `calc::effective_hourly_rate(cfg, mw)` 与 `calc::full_day_salary(cfg, mw, daily_h)`；weekbill 满勤日薪 = hourly 模式 wage×daily_h，day_rate 公式不变（wage×daily_h÷daily_h=wage） | 单点改动，weekbill/insights/发薪播报全链路自动继承；满勤假设与月聘模式一致 |
| 前端金额守卫 | 「有效时薪 > 0」统一口径：hourly ? wage>0 : monthly>0（hasSalary 类） | hourly 用户 monthly_salary=0 不应隐藏金额行 |
| hourly 模式 UI | 月薪/工作日覆盖/刷新工作日按钮隐藏，显示时薪输入 | 工作日分母在 hourly 口径下无意义 |
| 加班费率 | 不动（overtime_rate 是独立字段，两模式同义） | 加班费与时薪制无关 |

## 2. 分项设计

### 2.1 时间线回顾（Rust：insights.rs + cmds_bill.rs；前端：insights.js + index.html）

**数据结构**（命令 `get_day_timeline(offset: i64) -> DayTimeline`）：

```
DayTimeline { date, weekday, is_today, is_workday, total_front, total_events, hours: Vec<HourLine> }
HourLine { hour, work_secs, slack_secs, comm_secs, other_secs, front_secs, audio_secs, events, top_app: Option<String> }
```

- 一次 SQL 按 (hour, app) 聚合 app_usage_hourly，内存按 `app_usage::category_of` 归四类；act_hourly / audio_usage_hourly 各一条按 hour 聚合；
- top_app = 该小时前台秒最大的应用（展示用，不出本机）；
- 组装函数 `day_timeline_assemble(date, cfg, conn)` 纯函数可测；命令在 cmds_bill.rs 注册（build.rs 自动补 capabilities）。

**前端**：`BILL_TAB_KEYS` 加 "timeline"（pane `billTabTimeline`，圆点加在「身体账单」后）；`loadDayTimeline()` invoke 拉取 + `paintDayTimeline()` 渲染 24 行：小时标签 + 四色构成条（工作=金 / 摸鱼=红 / 沟通=蓝 / 其他=灰，比例按秒）+ 右侧「top_app · 键鼠 N 次」；行 title 给完整数字。头部汇总行：日期 · 前台 X.Xh · 键鼠 N 次 · 摸鱼率 Y%。日导航复用账单翻页器（timeline tab 下 pgStep 按天）。

### 2.2 周报图片（前端：bill.js/insights.js + 新命令 export_image）

- 触发：账单 tab 头部「存为图片」按钮（billData 为空时 toast 引导）；
- `buildReportModel(billData)`：把 PeriodBill 折成图片模型（纯函数，可被断言测试）——期号、日期范围、进账大数、基础/加班费（含时长）/摸鱼成本/摸鱼率、7（或 12/30）根桶条归一高度、最累/最摸日、金句档位（复用现有 quips 档位函数）；
- `drawReport(model)`：canvas 750×1050 逻辑尺寸、2x 物理密度；深底金字，与 app 视觉一致；
- 出口：`toBlob(png)` → base64 → `invoke("export_image", {filename: "niuma-周报-<period>.png", contentBase64})` 落下载目录；剪贴板可用时同时复制；
- export_image 与 export_csv 共用 `safe_download_path`（basename 清洗 + 下载目录回退链），返回最终路径给 toast。

### 2.3 时薪模式（Rust：config/calc/weekbill；前端：settings/bill）

- config 新字段：`salary_mode: String`（default "monthly"）、`hourly_wage: f64`（default 0.0）；
- calc：`effective_hourly_rate` hourly 分支直接取 `hourly_wage.max(0.0)`；`compute()` 其余链路零改动（earned = worked_h × rate）；
- weekbill：`full_day_salary` hourly 分支 = `wage × daily_h`；`day_rate = full_salary / daily_h` 公式不变；insights 趋势复用 period_bill 自动继承；休息日仍 0；未来日仍 0；
- settings：计薪方式分段（月薪 / 时薪）+ 时薪输入；mode 切换即显隐月聘三件套与「刷新工作日数据」按钮；load 回填 / readCfg 采集 / change 即存三处接线；
- 守卫：bill.js `hasSalary` 扩展为统一口径。
