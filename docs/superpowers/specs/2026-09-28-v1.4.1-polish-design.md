## 2. 分项设计

### 2.1 图标捐赠者机制（app_usage.rs）

**现状与根因**：`KNOWN_MAP`（L46）已把 `wechatappex.exe` 归一显示为「微信」（L50），但 `ensure_icon`（L367）按各自 exe 路径提取图标——小程序 / 内嵌页前台时前台进程是 WeChatAppEx.exe，提取到的是内嵌浏览器自身的图标，与微信主程序图标不符。显示名归一了，图标没跟着归一。

**改动**：

1. `KNOWN_MAP` 旁新增捐赠者表：

```rust
/// 图标捐赠者：显示名已归一、但 exe 自身图标不代表主程序的「马甲进程」。
/// 从马甲进程完整路径向上层目录找主程序 exe 借图标（同安装树内检索）。
const ICON_DONORS: &[(&str, &[&str])] =
    &[("wechatappex.exe", &["weixin.exe", "wechat.exe"])];
```

2. 新增 `fn donor_exe_path(exe_path: &str) -> Option<String>`：
   - 取 exe 文件名小写查 `ICON_DONORS`，未命中返回 `None`；
   - 命中则从**父目录**起向上最多 3 层，每层检查各捐赠者文件名是否存在（`Path::join` + `exists`；文件名比较不区分大小写）；检索**自浅而深**：目录层优先于捐赠者顺序，同层按表内顺序；
   - 第一个命中即返回捐赠者完整路径；全找不到返回 `None`。
   - 命中依据：微信安装形态 `...\Tencent\Weixin\WeChatAppEx\[ver]\WeChatAppEx.exe`，主程序在其上层的 `Weixin.exe`；≤3 层覆盖版本子目录嵌套。
3. `ensure_icon`（L367）提取前套一层：

```rust
let src = donor_exe_path(exe_path).unwrap_or_else(|| exe_path.to_string());
let val = match extract_icon_png(&src) { /* 原逻辑不变 */ };
```

   `audio_usage` 复用 `ensure_icon`（pub(crate)），捐赠者逻辑自动覆盖媒体来源，无需另行改动。

4. **缓存自愈**：`icon_path`（L352）文件名 `{:016x}.png` → `v2-{:016x}.png`。升级用户磁盘上已按显示名缓存了错误图标，仅改逻辑不会重算；版本前缀让旧缓存全部自然失效。旧文件成孤儿：**不清理**（几十个文件、每个几十 KB，不随时间增长），后续若碍事再加启动清扫。

**纪律不变**：`ensure_icon` / `cached_icon` 仍禁止在 `with_db` 回调里调用（ICON_CACHE ↔ DB 的 ABBA 死锁，函数注释原样保留）；本改动不触碰锁序。

**测试**（Rust 单测，tempdir 构造目录）：
- `WeChatAppEx\14153\WeChatAppEx.exe` + 上层 `Weixin.exe` → 返回 Weixin.exe 完整路径；
- 只有 AppEx、无捐赠者 → `None`；
- 非马甲 exe（如 code.exe）→ `None`（不查表直接短路）。

### 2.3 发布链路加固（scripts/publish_release.py）

**现状**（L485-513）：上传资产 → 按 id 取草稿终态核对 assets 与 latest.json 引用 → PATCH `draft=false`。PATCH 成功即返回 0，**没有发布后的可访问性验证**——上次发布正是靠重跑 + 人眼才发现问题。

**改动**：PATCH 成功（st==200）之后追加：

```python
# 发布后验证：此时 release 已公开、tag 引用才存在（草稿期 tags 端点 404 的
# 语义不变，上面的草稿查找仍走列表）。非 200 或仍是 draft 都算发布失败。
st, pub = gh.call("GET", "%s/releases/tags/%s" % (api, args.tag))
if st != 200 or pub.get("draft"):
    log("  [FAIL] post-publish verify: HTTP %s, draft=%s"
        % (st, pub.get("draft")))
    failed = True
```

既有「按 id 取终态 + assets / latest.json 核对」保持不变（那是草稿期核对，职责不同）。

**测试同步**（test_publish_release.py）：现有 fake 对 `GET /releases/tags/` 一律回 404（模拟草稿查找）。新验证同 URL 在 PATCH 之后必须 200，fake 需**带状态**：记录 PATCH `draft:false` 是否已发生，之后 tags 端点返回 `{"draft": false}`。补两条断言：
- 发布路径全绿 → 退出码 0，且发出过发布后的 tags GET；
- fake 强制 tags 端点返回 draft=true → 退出码 1。

### 2.5 导航日期补年份（frontend/app.js）

**现状**：三处 `slice(5)` 只显示月日（已定位）：
- L1972 `paintWeekBill`：`period_label · MM.DD–MM.DD`（账单 tab）；
- L2171 `paintBillNav`：`MM.DD–MM.DD`（热力 / 趋势 / 身体 tab 共用顶部导航）；
- L2404 趋势图悬停：`MM.DD–MM.DD · 入账 … · 摸鱼率 …`。

**改动**：新增 helper，三处替换调用：

```js
// 日期范围标签：同年右端省年份；跨年双侧都带（12.29–01.04 不再看不出年份）。
function fmtDateRange(startIso, endIso) {
  const f = (iso, withYear) => {
    const md = String(iso || "").slice(5).replace("-", ".");
    return withYear ? String(iso || "").slice(0, 4) + "." + md : md;
  };
  const sy = String(startIso || "").slice(0, 4);
  const ey = String(endIso || "").slice(0, 4);
  return f(startIso, true) + "–" + f(endIso, sy !== ey);
}
```

L1972 保留 `period_label · ` 前缀，仅换范围段。
