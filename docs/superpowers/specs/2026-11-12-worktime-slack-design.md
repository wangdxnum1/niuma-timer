# Working-time slacking statistics

User decision: new records use accurate working-time statistics; legacy hourly/day records are explicitly unavailable for recalculation, never proportionally estimated.

Only configured AM/PM working windows contribute to slacking numerator and denominator. Windows are half-open at minute boundaries; lunch and before/after work are excluded. Existing calendar/leave checks exclude non-working days from homepage and bill slacking indicators. Existing app classifications remain user override > default > other; all four categories participate in the denominator. Salary, overtime, raw app usage, audio usage and activity collection semantics stay unchanged.

Capture app usage into a new `app_usage_minutes(date, minute, app, seconds)` table, minute 0..1439. Store seconds within each minute, splitting the actual collected interval across minute/day boundaries. This supports minute-based configured work windows, including 09:30, without reconstructing unknown legacy timing or storing individual window events. Daily/hourly raw tables retain their existing values. All three writes share one transaction. Register the new table for backup version compatibility, retention and storage accounting, since version 1.11.6.

New `work_usage` Rust module provides `range(conn, start, end_exclusive, cfg) -> Result<HashMap<String, WorkUsage>>`; `WorkUsage { front_seconds: i64, slack_seconds: i64, legacy_seconds: i64 }` is serializable, Clone/Copy/Default. SQL groups minute rows by date/application, applying AM/PM union without double counting. `legacy_seconds` is daily raw app seconds minus all precisely captured minute seconds, clamped at zero. A day with mixed old/new records only evaluates precisely captured work-window seconds and discloses excluded legacy evidence. Changing configured windows or classification recomputes the precise records at query time.

AppUsageSummary adds `work_usage: Option<WorkUsage>` without altering raw apps/categories/hourly fields; None means the new calculation is unavailable. Homepage uses work_usage only and distinguishes zero entertainment with evidence from no evidence/legacy-only/unavailable data. Bills retain raw evidence for attendance/base salary branches but use new working-time seconds for slacking metrics. Add legacy-coverage metadata to period/day/bucket output so UI, trend, CSV and report image never turn unknown legacy evidence into a zero result. Mixed periods disclose that metrics cover new records only.

Tests cover fractional-hour windows, exact start/end, lunch, overnight splitting, count conservation and atomic rollback; legacy-only/mixed days; workday/holiday/leave; unchanged raw totals and salaries; UI/export unknown versus genuine zero. Preserve wheel paging and existing date navigation.
