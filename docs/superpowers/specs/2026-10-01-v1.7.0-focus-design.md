# 设计：v1.7.0——专注与顺手（专注时段 / 分类建议 / 月报图片）

日期：2026-10-01
状态：待用户确认后实施
方向裁决：用户于 2026-10-01 从三个候选中拍板「A 专注与顺手包」
前置：1.6.0 已发布（时间线 / 周报图片 / 时薪模式）

## 0. 定位与范围

1.6.0 完成回顾与分享后，记录侧数据维度已满。1.7.0 主轴定为**从记录走向指导**：

1. **专注时段统计**（主菜）：不只统计摸鱼率，还统计专注质量——每日专注段数、总专注时长、最长一段，进洞察区；
2. **应用分类智能建议**（轻）：对归入「其他」的应用给出一键分类建议，降低上手门槛；
3. **月报图片**（顺手）：周报图片管线补齐月跨度支持，分享闭环收口。

维持不做（理由不变）：跨平台、数据云同步、番茄钟类提醒。

## 1. 决策表

| 决策点 | 结论 | 理由 |
|---|---|---|
| 专注判定数据源 | 内存状态机实时判定，**段结束才落库一条** | 现有 act/app_usage 全是小时桶，粒度撑不起「连续 25 分钟」；逐分钟建表写入量无谓 |
| 状态机驱动点 | 复用 scheduler 节拍：每拍读「当前前台应用（app_usage）+ 最近输入时刻（activity 新增原子量）」 | 两路信号在各自模块已存在，focus.rs 只做纯状态机；不新开线程 |
| 活跃判定 | 最近输入间隔 < 5 分钟（与守护提醒的 idle 口径一致） | 全 App 统一「5 分钟无输入 = 已离开」 |
| 前台口径 | 仅「工作」类前台延长专注段；切到摸鱼/沟通/其他即断段 | 口径可解释：「专注 = 工作类应用的连续投入」；沟通类开会不断段的例外规则复杂度不值 |
| 达标线 | 连续 ≥ `focus_min_minutes`（默认 25，钳制 10–120）才记一段，不足丢弃 | 「专注段」定义本身就是达标线，丢弃是口径的一部分 |
| 手动暂停 | is_paused 即断段（同监控暂停语义：钱先冻结，专注也冻结） | 与暂停哲学一致，恢复后重新起算 |
| 跨午夜 | 段归属**开始日**，时长全程累计（end 可跨天） | 与加班「归属日由事件决定」精神一致；拆段复杂度不值 |
| 落库 | 新表 `focus_sessions (date, start_hm, end_hm, minutes, top_app)`；maintain 保留期清理同步纳入 | 单行轻量（每天几条到十几条）；数据主权与既有 7 表同待遇 |
| 洞察入口 | 新增第 6 个洞察 tab「专注」（周/月/年跨度 + 既有翻页导航，与身体账单同构） | 时间线是日粒度自导航，专注是周期聚合——两者导航语义不同，独立 tab 更清晰 |
| 无历史边界 | 上线当天开始积累，无数据期间如实显示空态 | 诚实数据原则；不回填不臆造 |
| 分类建议规则 | 纯关键词规则表（内置，离线可测），仅对「其他」类且当日前台 ≥10 分钟的应用给建议 | 不引入任何网络/模型依赖；建议只是加速手点，不自动改用户数据 |
| 月报图片 | 复用 1.6.0 canvas 管线：桶条自适应已支持 >12 不标标签；金句文案需按跨度换成「本月」措辞 | 管线已通用 80%，实际工作在文案与验收 |

## 2. 分项设计

### 2.1 专注时段（新模块 focus.rs + 命令 + 洞察 tab）

**采集状态机**（`focus.rs`，全部纯内存 + 结束时一次 INSERT）：

- 信号接入：`activity.rs` 的 WM_INPUT 回调里追加一个 `AtomicI64`（最近输入 epoch 秒，热路径零负担）；`app_usage.rs` 暴露当前前台应用展示名（已有内部状态，加只读访问器）；scheduler 每秒拍调 `focus::tick(now)`；
- tick 判定：`活跃 = now - last_input < 300s`；`工作 = category_of(当前前台) == 工作`；
  - 工作+活跃：无段则起段（记 start、累计 top_app 秒）；有段则延长；
  - 任一条件不满足：若已有段且时长 ≥ 阈值 → 落库（date=开始日, start_hm/end_hm, minutes, top_app）；无段或不足 → 丢弃并复位；
  - is_paused：同「不满足」处理（断段）；
  - 跨午夜：段归属开始日，跨天不拆（end_hm 可能 < start_hm，前端显示「次日」）；
- 配置：`focus_enabled`（serde default true）、`focus_min_minutes`（default 25，钳 10–120）——设置页守护卡追加两个控件（三处接线同既有模式）；
- 命令：`get_focus_summary(span, offset)`（周/月/年，快照模式同 get_bill）返回逐日 `{sessions, total_min, longest_min, longest_hm}` 与周期汇总；
- 洞察 tab「专注」：四张 KPI 卡（总段数 / 总专注 / 最长一段 / 日均专注）+ 逐日单金柱（复用身体账单的渲染模式）+ 最专注一天注脚；空态「专注统计自 v1.7.0 起积累」。

### 2.2 应用分类智能建议

- `app_usage.rs` 新增 `suggest_category(display) -> Option<&'static str>`：关键词规则表（code/idea/studio/dev/studio→工作；wechat/qq/dingtalk/slack/telegram/mail→沟通；bilibili/youtube/game/video/music→摸鱼；大小写不敏感，仅当该应用既不在用户分类也不在 DEFAULT_CATEGORIES 时返回 Some）；
- 前端应用明细页：归「其他」且当日前台 ≥10 分钟的行，在分类 chips 尾部追加一枚虚线建议 chip「建议：工作」（金色描边）；点击写入 `cfg.app_categories[app]` 并走既有重算路径；
- 不自动生效：建议只加速手点，用户不点不变。

### 2.3 月报图片

- `buildReportModel` 已按桶数自适应；需补：金句文案按跨度分档（week 本周 / month 本月，年跨度禁用存图按钮并提示「年账单暂不支持图片」）；按钮文案与文件名跟随期号；
- 验收：月跨度出图（30 桶不标标签、工作日柱正确）、周跨度回归不变。

- Rust：focus 状态机单测（达标/丢弃/断段/暂停/跨午夜/阈值边界）、聚合单测、suggest_category 规则单测；cargo fmt/clippy/test 全绿；
- 前端：新增 `test_focus.js`（命令契约 + 口径 + tab 结构 + 空态）、`test_suggest_category.js`（规则表 + 建议 chip 触发条件 + 不自动生效）、test_report_image.js 扩展月跨度断言、test_settings.js 扩展专注控件接线；run_all 全绿；
- 漂移守卫 + README 双语（test_readme）+ CHANGELOG；
- 发布：PR CI 绿合并 → `release.bat 1.7.0`（网络受限时走既定 API 应急通道）→ 云端验收。

## 4. 风险与回退

| 风险 | 缓解 |
|---|---|
| WM_INPUT 热路径新增原子写 | 单次 AtomicI64 store，纳秒级；基准不变则保留 |
| 专注段误判（远程会话/挂机） | 远程活跃期间输入来自远程设备——与加班排除共用 remote::is_remote_active 判定，远程期间不起段不延长 |
| 第 6 个洞察 tab 拥挤 | 翻页器圆点已验证 5 个，6 个仍在宽度内；金句文案按跨度分档防止「本周」串味 |
| 上线初期无数据困惑 | 空态文案明确「自 v1.7.0 起积累」 |
