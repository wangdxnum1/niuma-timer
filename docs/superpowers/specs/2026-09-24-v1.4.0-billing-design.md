## 0. 背景与目标

现状：「账单」视图（`index.html:225`）已有 4 个 tab——本周账单 / 时段热力 / 多周趋势 / 身体账单——但时间维度**只有周**。用户看得到「这周赚了多少」，看不到「这个月」和「今年」。

本设计要达成：

1. **月账单 / 年度账单**：账单视图加**跨度切换器**（周 / 月 / 年），4 个 tab 随跨度重算。
2. **发薪日战绩通知**：发薪日当天首次启动时，用一条系统通知把上月战绩送到眼前（情绪价值）。

### 关键发现：后端已经是「按区间取数」

查证 `src-tauri/src/insights.rs` 与 `weekbill.rs` 后确认，**周以外的时间维度几乎没有新增工作量**：

| 现有件 | 现状 | 结论 |
|---|---|---|
| `weekbill::assemble` | 已按天取 `monthly_workdays_of(d.year(), d.month())`（`weekbill.rs:254`），跨月工资天然正确 | 只需把 `for i in 0..7` 泛化为任意区间 |
| `insights::hour_heatmap_assemble(ws, we, conn)` | 入参已是**日期区间** | 直接复用 |
| `insights::body_bill_assemble(ws, we, conn)` | 入参已是**日期区间** | 直接复用 |
| `insights::week_bounds(week_offset)` | 唯一的「周专属」函数：偏移 → 区间 | **唯一**需要泛化的点 |

因此本设计的后端改造是**低风险**的：把「周偏移」泛化为「跨度 + 偏移」。

## 1. 决策表

| 决策点 | 结论 |
|---|---|
| 界面落位 | **账单视图加跨度切换器**（周 / 月 / 年），不新增 rail 项、不新增独立视图 |
| 月 / 年口径 | **自然月**（1 号 ~ 月末）/ **自然年**（1 月 1 日 ~ 12 月 31 日）；不用计薪周期 |
| 分桶粒度 | 周 → 7 个天桶；月 → 该月天数的天桶；年 → 12 个月桶（**由 Rust 计算并单测**，不在前端做分桶） |
| 环比 | 周 → 上一周；月 → 上一月；年 → 上一年 |
| 趋势 tab | 窗口随跨度：周 → 最近 8 周；月 → 最近 8 个月；年 → 最近 8 年 |
| 命令形态 | 现有 `get_week_bill` / `get_hour_heatmap` / `get_week_trend` / `get_body_bill` **改名**为跨度通用名并新增 `span` 参数（见 §2.4） |
| 发薪日通知时点 | 发薪日（`config.payday`）**当天首次启动**发一次，按日期去重 |
| 发薪日战绩口径 | **上一个自然月**（理由：10 号发的是上月工资，报上月才是「这笔钱对应的工作」） |
| 发薪日通知载体 | 系统通知 + 托盘兜底，复用 `remind::notify()` |
| 跨度记忆 | 记入配置 `bill_span`，下次打开沿用 |

## 2. 后端改动

### 2.1 新增跨度类型与区间函数

在 `weekbill.rs` 引入（或新建 `period.rs`，实施时按耦合程度二选一，优先放 `weekbill.rs` 以避免新模块）：

```rust
/// 账单时间跨度
pub enum Span { Week, Month, Year }

/// 跨度 + 偏移 → 闭区间 [start, end]（偏移 0 = 当前周期，负值不合法按 0 处理）
pub fn period_bounds(span: Span, offset: i64, today: NaiveDate) -> (NaiveDate, NaiveDate);

/// 上一周期区间（供环比）
pub fn prev_period_bounds(span: Span, offset: i64, today: NaiveDate) -> (NaiveDate, NaiveDate);
```

- `Span::Week` 分支必须与现有 `week_bounds` / `week_start_of` **逐位等价**（搬迁而非重写），并以既有测试 `week_bounds_caps_future`、`week_start_alignment` 回归。
- 未来封顶语义沿用现有 `week_bounds_caps_future`（不可看未来）。

### 2.2 `assemble` 泛化为任意区间

- `WeekInput` → `PeriodInput`：`week_start: NaiveDate` 改为 `start: NaiveDate` + `end: NaiveDate`（闭区间）。
- 主循环 `for i in 0..7` → 按天数迭代 `start..=end`。
- **工资口径一行不改**：`monthly_workdays_of` 已按天取当月分母（`weekbill.rs:254`），`today` 实时 / 未来 0 逻辑与区间无关，天然适用。
- `WeekBill` → `PeriodBill`：`week_start`/`week_end`/`week_no`/`is_current_week` 改为 `period_start`/`period_end`/`period_label`/`is_current_period`；其余字段原样保留（前端改动面最小化）。
- `period_label` 取值：周 → 「第 37 周」；月 → 「2026 年 9 月」；年 → 「2026 年」。

### 2.3 新增分桶函数（本设计的核心新增逻辑，重点单测）

```rust
/// 把逐日账单按跨度折成分桶：周/月 → 天桶；年 → 月桶
pub fn bucketize(days: &[DayBill], span: Span) -> Vec<BucketBill>;
```

- `BucketBill` 字段与 `DayBill` 对齐（`label`、`salary`、`ot_total`、`slack_seconds`、`act_events`、`keys`、`clicks`、`slack_rate`、`has_record`），并把 `weekday` 改为通用的 `label`。
- 年桶：12 项，按月合并 `salary`/`ot_total`/`slack_seconds`/计数类字段；`slack_rate` = 该月 `slack_seconds ÷ 该月工作日四类前台秒`（**分子分母各自求和后再相除**，不是比率的平均——这是最容易写错的地方，必须有专测）。
- 月桶：等于该月每一天（与周桶同构），保证前端只有一种渲染路径。

### 2.4 命令改造

现有 4 条命令各加 `span: String` 入参并改为跨度通用名：

| 旧名 | 新名 | 入参 |
|---|---|---|
| `get_week_bill` | `get_bill` | `span, offset` |
| `get_hour_heatmap` | `get_heatmap` | `span, offset` |
| `get_week_trend` | `get_trend` | `span, offset` |
| `get_body_bill` | `get_body_bill`（名字本已通用） | `span, offset` |

- `span` 以字符串传入（`"week"` / `"month"` / `"year"`），解析失败 → 明确 `Err`，**不静默回退**为 week（静默回退会掩盖前端 bug）。
- `get_trend` 的窗口随跨度：周 8 周 / 月 8 月 / 年 8 年。
- **capabilities 收尾**：`build.rs` 的 `sync_capabilities` 只会**新增** `allow-*`、不会删除。改名后需**手工删除**遗留的 `allow-get-week-bill` / `allow-get-hour-heatmap` / `allow-get-week-trend`，并在新增的断言脚本中校验「不存在陈旧权限项」（见 §6）。

### 2.5 发薪日战绩通知（`remind.rs`）

- 复用现有提醒骨架：`notify()`、按日期去重的「当天一次」机制（与下班提醒同构，参考 `LAST_OFFWORK_REMIND` 一类静态量的做法）。
- 触发条件：`config.remind_payday_enabled` 为真 **且** 今天 `day == config.payday` **且** 今天尚未发过。
- 触发时机：当天首次启动（在 `.setup` 之后的下班提醒 tick 内联判断即可，不必新增线程）。
- 文案内容：取**上一个自然月**的账单（`period_bounds(Span::Month, 1, today)`），示例：

```
title: 发薪日到了，牛马
body:  9 月战绩：出勤 21 天 · 加班 12.5h · 摸鱼率 23% · 折合进账 ¥11,240
```

- 「折合进账」= 上月账单的 `total_income`。
- 复用现有提醒的开关体系与暂停语义（暂停监控期间的提醒策略与既有提醒保持一致）。

## 3. 前端改动

### 3.1 `index.html`

- `viewBill` 的头部（现有 `month-nav`，`index.html:226`）之前加入**跨度切换器**（三段式：周 / 月 / 年），复用现有 `.mon-seg` 分段控件样式。
- 偏移导航（‹ ›）保留，语义变为「上一个/下一个周期」，跨度变了步长随之变。
- 设置页新增「发薪日战绩提醒」开关（绑定 `remind_payday_enabled`）。

### 3.2 `app.js`

- `get_week_bill` → `get_bill(span, offset)`；同理替换 `get_hour_heatmap` / `get_week_trend` 的调用名并传 `span`。
- 图表由读 `days[]` 改为读 `buckets[]`（分桶已在后端算好）。
- 切换跨度时重置 `offset` 为 0 并重新拉取 4 个 tab 的数据。
- 跨度写入 `config.bill_span` 并随 `save_config` 持久化；`load()` 时读回。
- 趋势 tab 的 X 轴标签按跨度切换（周/月/年），沿用后端返回的 `label`。

## 4. 行为变更清单（用户可感知）

1. 账单视图顶部出现「周 / 月 / 年」切换器；切换后 4 个 tab 全部按新跨度重算。
2. 年度视图的柱/趋势图按月呈现（12 个月），不是 365 根柱子。
3. 上次选的跨度会被记住。
4. 发薪日（默认 10 号）首次启动，收到一条上月战绩通知。

## 5. 配置项（`config.rs`）

新增（均 `#[serde(default)]`，同步 `Default` impl 与 merge 白名单）：

```rust
/// 账单视图上次选择的跨度："week" / "month" / "year"
#[serde(default = "default_bill_span")]
pub bill_span: String,
/// 发薪日战绩提醒开关
#[serde(default = "default_true")]
pub remind_payday_enabled: bool,
```

- `default_bill_span()` 返回 `"week"`。
- `remind_payday_enabled` 的默认值**与既有提醒开关（`remind_sedentary_enabled`）保持一致**，实施时照抄其默认写法。

## 6. 测试影响

| 类型 | 内容 |
|---|---|
| Rust 单测（`weekbill.rs`） | `period_bounds`：周分支与旧 `week_bounds` 等价（保留原测试）、月首/月末（含 2 月与闰年）、年首/年末、偏移正确性、未来封顶 |
| Rust 单测（`bucketize`） | 周=7 桶；月=该月天数桶；年=12 桶；**年桶 `slack_rate` 必须是「求和后再相除」**（构造两个不同比率的月份验证不等于简单平均）；空数据桶 |
| Rust 单测（`assemble` 泛化） | 保留全部既有 9 条口径测试；新增：跨月区间的月/年聚合与逐日求和一致（对拍） |
| Rust 单测（发薪日） | 触发日判定（payday 命中/不命中）、当天去重、上月区间选取（跨年：1 月的上月是去年 12 月） |
| `scripts/test_bill.js`（新增） | 断言：4 条命令均新增 `span` 入参（其中 3 条改名，`get_body_bill` 仅加参）；`capabilities/default.json` 无陈旧 `allow-get-week-bill` / `allow-get-hour-heatmap` / `allow-get-week-trend`；跨度切换器元素存在；`bill_span`/`remind_payday_enabled` 字段存在且默认值正确 |
| `test_settings.js` | 覆盖新增的「发薪日战绩提醒」开关（与包 D+F 的 test_settings 补强合并进行） |
| 既有脚本（**改名连带必改**） | `test_week_bill.js` 3 条（命令 `get_week_bill` / handler 登记 / `invoke("get_week_bill", { weekOffset })`）；`test_insights.js` 9 条（3 条命令名 `get_hour_heatmap`/`get_week_trend`/`get_body_bill` + 3 条 handler 登记 + 3 条 `invoke(...)`）。两条脚本均改为新命令名 + 新入参 `{ span, offset }`；`run_all.js` 复核 |

## 7. 验收与手测清单

1. 账单视图切到「月」→ 4 个 tab 均按当月重算；‹ › 按月步进；跨月边界（月末/月初）数据不错位。
2. 切到「年」→ 趋势图 12 个点而非 365；年桶摸鱼率与「按月手算」一致。
3. 重启 → 跨度为上次选择的值。
4. 把 `payday` 改成今天、重启 → 收到上月战绩通知；再重启一次 → 不再重复。
5. 关闭「发薪日战绩提醒」→ 重启 → 无通知。
6. `node scripts/run_all.js` 全绿；`build.bat test` 全绿。
