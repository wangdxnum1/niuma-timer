## 0. 背景与目标

niuma-timer 目前**没有任何自动更新能力**：用户必须手动来 GitHub Releases 下载新版并覆盖。分发形态有两条腿——NSIS/MSI 安装版与绿色版 portable exe——两者都需要更新通道。

本设计要达成的目标：

1. **A1 核心自动更新**：应用能发现自己有新版本并完成升级，用户零手动干预。
2. **A2 升级后更新公告**：升级完成后首次启动，展示本次更新内容，让用户知道变了什么。
3. 基础件：托盘「检查更新」入口、设置页「自动检查更新」开关、「跳过此版本」。

### 硬约束（已查实，设计必须绕开）

| 约束 | 含义 |
|---|---|
| Tauri updater 在 Windows **只支持 NSIS / MSI 安装包** | 不支持绿色版 exe；绿色版必须自研更新路径 |
| Windows 桌面**通知拿不到点击回调** | `tauri-plugin-notification` 的 Actions 仅移动端支持；不能靠「点通知打开更新窗」 |
| Windows 通知**仅对已安装应用可靠** | 绿色版无开始菜单快捷方式 / AUMID 注册，Toast 可能弹不出或显示为 PowerShell |
| `tauri_plugin_single_instance` 会顶掉已运行实例 | 更新助手进程若初始化 Tauri，会把用户主进程踢掉 |
| 运行中的 exe 不可覆盖 / 删除（可改名） | 绿色版替换必须「改名旧 exe → 落新 exe」 |

### 关于签名的重要澄清

本设计的「签名」是 **Tauri updater 的 minisign 签名**，与 Authenticode 代码签名（SmartScreen 信誉）**完全无关**：

- minisign 密钥对由 `tauri signer generate` 本地生成，**免费**；
- 公钥写入 `tauri.conf.json`，私钥只存在于本地环境变量与发布环境；
- **签名强制不可关**：updater 拒绝未签名或签名不符的包，这是安全底线；
- 它**不会**改善 SmartScreen 警告，也不会改变「未知发布者」——那是 Authenticode 的职责，本轮**明确不做**（用户已裁决「暂不动」）。

## 1. 决策表

| 决策点 | 结论 |
|---|---|
| 更新形态 | **两条腿都做**：安装版走官方 `tauri-plugin-updater`；绿色版走自研内置助手模式 |
| 安装版 / 绿色版判定 | 查注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall` 下是否存在本应用卸载项（项目已有 `winreg` 依赖）；命中 = 安装版，未命中 = 绿色版 |
| 检查节奏 | **低频**：启动后延迟约 30 秒首次检查，之后每 6 小时一次；加随机抖动避免齐打；离线/失败静默重试 |
| 提示载体 | **托盘为主 + 通知兜底**：托盘 tooltip 追加「（有新版本 vX.Y.Z）」+ 右键菜单动态出现「更新到 vX.Y.Z」项；同时尽力发系统通知，失败静默忽略 |
| 托盘角标图标 | **不做**：`icon_render.rs` 现仅提供 `static_icon()`，无叠加渲染能力，不为此新增渲染链路 |
| 更新窗形态 | **复用主窗口内视图** `viewUpdate`（与 `viewMain`/`viewBill`/`viewSettings` 并列）；托盘点击即 `showView("viewUpdate")`，不新建独立窗口 |
| 自动更新范围 | **A1 + A2**；不含 A3（双通道）；「检查更新」入口与自动检查开关作为 A1 基础件 |
| 跳过版本 | **要**：`update_skipped_version` 记录被跳过的版本，之后不再提示该版，直到出现更新的版本 |
| 绿色版完整性校验 | **复用 `SHA256SUMS.txt`**（发布脚本已产出）；不引入额外 minisign `.sig` 分支（安装版仍由 updater 强制验签） |
| A2 更新内容来源 | **编译期嵌入 CHANGELOG**：`build.rs` 取 `CHANGELOG.md` 本版本段落，经 `cargo:rustc-env` 注入 exe；离线可用、无 API 限流 |
| 换行/日志 | 助手模式全程写 `db::debug_log`，便于失败排查 |

## 2. 总体架构

```
                    ┌─ 检查更新（30s 后首次 + 每 6h）
                    │     查 GitHub Releases 的 latest.json
                    ▼
              有新版本？──否──▶ 静默结束
                    │是
                    ▼
        版本 == update_skipped_version ？──是──▶ 静默结束
                    │否
                    ▼
        托盘 tooltip + 动态菜单项 + 通知兜底 ──▶ 用户点开 viewUpdate
                    │
                    ▼
            ┌───────┴────────┐
            ▼                ▼
      安装版判定             绿色版判定
   （注册表有卸载项）      （注册表无卸载项）
            │                │
            ▼                ▼
  官方 updater 下载      内置助手模式：
  -setup.exe 并静默      --apply-update 参数
  运行安装器              见 §6
            │                │
            └───────┬────────┘
                    ▼
            重启后首次启动 ──▶ A2 展示更新公告（viewUpdate）
```

## 3. 签名与密钥

1. 生成密钥对（一次性，本地执行，**不入库**）：

```
tauri signer generate -w ~/.tauri/niuma-timer.key
```

2. 公钥写入 `src-tauri/tauri.conf.json` → `plugins.updater.pubkey`。
3. 私钥与口令通过环境变量注入构建：
   - `TAURI_SIGNING_PRIVATE_KEY`（私钥内容或路径）
   - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`
4. `release.bat` 在进入 build 步骤前校验这两个环境变量是否就绪，缺失则**直接报错退出**并提示如何设置（避免产出一个没有签名的包、到用户侧才发现更新被拒）。
5. 新增 `.gitignore` 条目：`*.key`，防止私钥误入库。

## 5. 后端改动

### 5.1 新增模块 `src-tauri/src/update.rs`

单一职责：版本发现、版本比较、更新状态机。**所有纯逻辑必须可单测**。

- **纯函数（重点测试对象）**：
  - `compare_versions(a: &str, b: &str) -> Ordering`：手写语义化版本比较，覆盖 `1.10.0 > 1.9.0`（数字比较而非字符串）、不等长（`1.4` vs `1.4.0`）、预发布后缀（`1.4.0-beta.1 < 1.4.0`）等。不引入 `semver` 依赖（与项目既有的「手写 FNV-1a / 手写 CHANGELOG 抽取」风格一致）。
  - `parse_latest_json(s: &str) -> Result<RemoteRelease, String>`：解析远端清单，字段缺失/格式错误返回明确 Err。
  - `should_notify(remote_ver, current_ver, skipped: Option<&str>) -> bool`：综合版本比较与跳过记录。
  - `parse_helper_args(argv: &[String]) -> Option<HelperArgs>`：解析 `--apply-update` 助手参数。
- **薄 IO 层**：网络请求（复用 `reqwest`，已为依赖）、注册表探测（复用 `winreg`）、文件替换，均以窄接口包住，便于注入假实现。

### 5.2 安装版 / 绿色版判定

新增 `update::is_installed() -> bool`：遍历 `HKCU\...\Uninstall` 子键，匹配 `DisplayName` 含本应用名。失败（读不到注册表）保守返回 `false`（走绿色版路径，纯文件替换，不需要管理员权限，更安全）。

### 5.3 检查调度

- 在 `main.rs` 的 `.setup` 中起一个线程：
  - 先 `sleep(30s)`；
  - 若 `cfg.update_auto_check` 为 false 则直接结束；
  - 之后循环：执行一次检查 → `sleep(6h ± 抖动)`。
- 检查失败（网络异常、解析失败、无更新）一律静默，仅写 `debug_log`；不弹任何 UI。
- 手动「检查更新」走独立的一次性命令，**不受** `update_auto_check` 开关限制，结果要给出可见反馈（成功/已是最新/失败原因）。

### 5.4 新增命令

```rust
/// 一次检查更新的结果（`check_update` 返回体，前端据此渲染 viewUpdate）
#[derive(Debug, Clone, serde::Serialize)]
pub struct UpdateInfo {
    /// 当前版本（`env!("CARGO_PKG_VERSION")`）
    pub current: String,
    /// 远端版本；无更新时等于 current
    pub latest: String,
    /// 是否有可用更新
    pub has_update: bool,
    /// 远端更新说明（来自 latest.json 的 notes）
    pub notes: String,
    /// 安装版 or 绿色版（决定「立即更新」走哪条路径，前端据此提示文案）
    pub installed: bool,
    /// 检查失败原因；Ok 时为空
    pub error: Option<String>,
}

/// 检查更新；手动入口调用。返回远端版本与是否有更新，供前端渲染 viewUpdate
#[tauri::command]
fn check_update(app: tauri::AppHandle) -> Result<UpdateInfo, String>;

/// 开始执行更新（安装版静默装 / 绿色版起助手进程）
#[tauri::command]
fn start_update(app: tauri::AppHandle) -> Result<(), String>;

/// 跳过某版本（写入 update_skipped_version）
#[tauri::command]
fn skip_update_version(app: tauri::AppHandle, version: String) -> Result<(), String>;

/// 取本次更新公告（编译期嵌入的 CHANGELOG 段落 + 是否刚升级）
#[tauri::command]
fn take_update_announcement(app: tauri::AppHandle) -> Option<String>;
```

命令名单由 `build.rs` 的 `command_names()` 自动解析并补齐 `capabilities/default.json`，无需手工维护 ACL（见 `build.rs` 注释中的历史教训）。

### 5.5 托盘菜单（`tray.rs`）

- 现有 4 项（主界面 / 刷新工作日 / 暂停监控 / 退出）的构建见 `tray.rs:608-642`。
- 新增：
  - 静态项「检查更新」→ 触发一次手动检查（结果落到 `viewUpdate`）。
  - **动态项**「更新到 vX.Y.Z」：发现新版本后动态插入，点击 `showView("viewUpdate")`；未发现时不存在。
  - tooltip 在有新版本时追加「（有新版本 vX.Y.Z）」。
- 托盘图标**不换**（无角标渲染能力，见 §1）。

### 5.6 配置项（`config.rs`）

新增字段（均带 `#[serde(default)]`，向后兼容旧 `config.json`），并同步 `Default` impl 与 merge 白名单：

## 6. 绿色版自更新：内置助手模式

### 6.1 入口拦截（关键）

`main()` **最开头**解析 `std::env::args()`：

- 若命中 `--apply-update` → 调用 `update::run_helper(args)`，纯 Rust 同步流程，**完全不初始化 Tauri**，结束即 `std::process::exit(...)`。
- 这样彻底绕开 `tauri_plugin_single_instance`（`main.rs:729`）——助手进程不会把用户主进程顶掉。
- 这是唯一必须在 Tauri 之前执行的逻辑，代码要放在 builder 链之前并加显著注释说明原因。

### 6.2 参数

```
niuma-timer.exe --apply-update \
    --target <当前 exe 绝对路径> \
    --wait-pid <父进程 pid> \
    --url <新 exe 下载地址> \
    --sha256 <期望哈希>
```

### 6.3 流程与回滚

1. 轮询等待 `--wait-pid` 退出（带超时，如 30 秒；超时视为失败）。
2. 下载 `--url` 到同目录临时文件（同目录保证后续 `rename` 是同卷操作，避免跨卷失败）。
3. 计算 SHA256，与 `--sha256` 比对；不符 → 失败。
4. 写为 `<target>.new`。
5. 旧 exe 改名 `<target>.old`。
6. `.new` 改名为 `<target>` 就位。
7. 拉起新 exe。
8. 成功 → 删除 `.old`，退出码 0。
9. **任一步失败** → 尽力恢复 `.old` 为 `<target>` → 拉起旧 exe → 写 `debug_log` → 退出码非 0。
10. 失败时发一条系统通知（若通知通道可用）告知「更新失败，已回滚」。

期望哈希来源：主进程在启动助手前，从同 Release 的 `SHA256SUMS.txt` 取对应条目。

## 8. `build.rs` 注入更新公告（A2）

沿用现有 `cargo:rustc-env` 注入范式（见 `build.rs:281-287` 的 `BUILD_TIME` / `BUILD_GIT` / `BUILD_FE_VER`）：

- 新增读取 `../CHANGELOG.md`，抽出与 `CARGO_PKG_VERSION` 匹配的 `## [x.y.z]` 段落，`println!("cargo:rustc-env=UPDATE_NOTES={...}")`。
- 抽取逻辑需处理多行、含引号与换行转义；注意 `rustc-env` 值中的换行处理，必要时以 `\n` 转义后再在运行时还原。
- `println!("cargo:rerun-if-changed=../CHANGELOG.md")`，确保改 CHANGELOG 后重新注入。
- 抽不到段落时降级为空串（不 panic），运行时 A2 界面显示「暂无更新说明」。
- 抽取逻辑本身可在 `build.rs` 内以纯函数形式实现并加单测（项目已有 `build.rs` 内联逻辑的先例，如 `command_names()`）。

## 9. 行为变更清单（用户可感知）

1. 启动约 30 秒后自动检查更新；此后每 6 小时一次；也可从托盘「检查更新」手动触发。
2. 发现新版本：托盘 tooltip 提示 + 托盘菜单出现「更新到 vX.Y.Z」；安装版通常还能收到一条系统通知（绿色版可能收不到，属预期）。
3. 点托盘项 → 主窗口切到「更新」视图，可「立即更新 / 跳过此版本 / 稍后」。
4. 安装版点「立即更新」→ 下载安装包并静默升级，随后自动重启。
5. 绿色版点「立即更新」→ 下载新 exe、校验哈希、退出并替换、自动拉起新版；失败自动回滚并告知。
6. 升级后首次启动 → 自动展示本次更新内容（A2）。
7. 设置页可关闭「自动检查更新」（手动检查仍可用）。

## 11. 验收与手测清单

1. 无网络时启动 → 无报错、无弹窗、`debug_log` 记录检查失败。
2. 把 `latest.json` 的版本号改成大于当前版本 → 重启 → 托盘出现「更新到 vX.Y.Z」，点开进入 `viewUpdate` 并显示更新说明。
3. 点「跳过此版本」→ 重启 → 不再提示该版本；把远端版本再抬高一位 → 重新提示。
4. **安装版**：在装有旧版的机器上点「立即更新」→ 下载、静默安装、重启为新版。
5. **绿色版**：手动调用助手参数流程 → 新 exe 就位、旧 exe 变 `.old` 后删除、新进程起来；人为篡改 `--sha256` → 观察到回滚且旧版照常运行。
6. 关掉「自动检查更新」→ 重启 → 不再自动检查；点托盘「检查更新」仍能工作。
7. 升级后首次启动 → 自动展示公告；再次启动 → 不再展示。
8. `node scripts/run_all.js` 全绿；`build.bat test` 全绿；`build.bat release` 产出 `.sig`。

## 12. 风险与降级

| 风险 | 应对 |
|---|---|
| 首次发布后用户无自动更新能力（bootstrapping） | 已接受：v1.4.0 仍是手动分发的最后一版，之后即可自动更新 |
| 绿色版替换被安全软件拦截 | 失败即回滚 + 日志 + 通知；不静默失败；文档提供手动覆盖指引 |
| `latest.json` 平台键取值与实际产物不符 | 实施时以真实产物核对，不臆测；发布校验增加断言 |
| 下载源受限（国内网络） | 更新失败静默重试；`viewUpdate` 提供「手动下载」链接（指向 Release 页） |
| 助手进程残留 | 等待父进程带超时；进程退出前尽力清理临时文件 |
