## 设计

### 第一段：内容前置（手动，单独一笔提交）

1. **CHANGELOG.md**
   - `## [未发布]` → `## [1.1.0] - 2026-09-18`
   - 文件底部（`[1.0.0]:` 行旁）补：`[1.1.0]: https://github.com/wangdxnum1/niuma-timer/releases/tag/v1.1.0`
   - 提交前通读该段一遍：发布说明将逐字来自这里，公开即难撤
2. **README.zh-CN.md**
   - 版本行：`当前版本 **1.0.0**（2026-09-10）` → `当前版本 **1.1.0**（2026-09-18）`
   - 功能列表补 1.1 亮点：**追加到现有功能列表末尾**（不重排既有条目、不新建分组标题），
     每条沿用既有「**加粗短名**——描述」条目式风格：
     周账单（小票/仪表盘双风格）、摸鱼成本货币化（实时烧钱行 + 四档文案）、
     应用四分类（工作/摸鱼/沟通/其他，可覆盖）、跨午夜加班归属、
     节假日/休息日加班独立起算与费率、历史回看（明细翻月 / 活动·应用·媒体翻日）+ CSV 导出、
     存储占用细分与一键整理、远程会话识别（RDP/向日葵/ToDesk/UU 防误判加班）
3. **README.md（英文版）**：同步上述版本行与功能条目的对应英文
4. **提交**：`docs(release): CHANGELOG 定稿 1.1.0 并补全双语 README 功能列表`
   - 必须先于发布执行：release.bat 第 8 步用 `git add -A` 扫盘，
     内容变更混进 `release: v1.1.0` 提交会污染发布历史
   - 本设计文档随该笔一并提交

### 第二段：一键发布（release.bat 全自动）

5. 确认 Clash 在 127.0.0.1:7890 监听（push 与 API 发布都依赖它；
   `publish_release.py` 走 `NIUMA_PROXY` 默认 7890）
6. 运行 `release.bat 1.1.0 /y`（AI 终端无法应答脚本的 `set /p` 交互，人工确认点
   前移到聊天里的预检步骤），自动完成：
   - 版本同步 Cargo.toml + tauri.conf.json，并重解析校验
   - 步骤 0：cargo test + 15 个前端断言脚本，全绿才继续
   - release 构建 → NSIS + MSI + 便携 exe（`bin\package`）
   - 展示 `git status --porcelain` 后 `git add -A` 提交 `release: v1.1.0`
     （此时预期 diff 仅：Cargo.toml / tauri.conf.json 版本号；缓存戳指纹不变）
   - tag v1.1.0 + push（自动检测代理，openssl 后端）
   - GitHub Release：notes 取 CHANGELOG `[1.1.0]` 段，上传产物 + SHA256SUMS.txt，标 latest
7. 若 push/发布失败：按脚本打印的手动命令恢复（代理未开 / 远程 tag 冲突两类提示已有）

### 第三段：发布后核对

8. Release 页面核对：
   - 资产齐全（NSIS exe、MSI、便携 exe、SHA256SUMS.txt），notes 非空且含 1.1 内容，latest 标记
   - tag v1.1.0 指向 main 上的发布提交
9. 可选冒烟：下载便携 exe 本地运行，确认悬停卡与「账单」tab 正常加载（WebView2 新缓存戳生效）

## 错误处理与回滚

- 测试失败：脚本自动中止，工作区只余版本号改动，`git checkout -- src-tauri\Cargo.toml src-tauri\tauri.conf.json` 即可还原
- 发布说明取错段：不会发生——`[1.1.0]` 段存在且格式已按解析器要求书写；若回退 `[未发布]` 说明第一步遗漏，立即停止检查
- Release 内容有误且必须撤回：删除远端 tag + Release，修复后重跑 `release.bat 1.1.0`（本地 tag 由脚本提示重建）

- 不动测试脚本与 lib 抽取（用户既定「先不动」约束）
- 不改 release.bat / publish_release.py 发布逻辑本身
