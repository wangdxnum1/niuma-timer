## 用户验收（先备份，勿直接用唯一一份日常数据试还原）

1. 运行 `bin/package/niuma-timer-1.4.0-portable.exe`，检查版本 1.4.0。
2. 账单的四个子页切换周/月/年，快速切换后内容应对应最终选择；年度身体账单按实际有记录天数计算日均。
3. 设置里修改发薪日提醒、自动检查更新开关；退出重启后设置应保留。
4. 点击“立即备份”，核对提示与列表路径；压缩包应包含 manifest、数据库与配置（存在时）。
5. 在可丢弃的测试账户/数据副本上：备份 → 改工资/加班记录 → 还原 → 自动重启，检查数据回到备份状态、保护性备份与旧库留存文件存在。
6. 损坏压缩包应显示不可用或报错，不应覆盖当前数据库或重启。
7. 检查更新页能显示当前版本；无网络时应给出可读错误。真正下载、安装、重启及升级公告仍需可用的新版本发布源进行端到端验收。

## 发布边界

- 没有运行 `release.bat`，没有 push、创建 Release 或公开任何资产。
- 自动更新私钥保存在项目外 `C:\Users\Tim\.tauri\niuma-timer.key`；公钥已配置到客户端。私钥未加口令，应单独安全备份，不要发送或提交。
- 本机 Tauri 构建工具需要 `TAURI_SIGNING_PRIVATE_KEY`；构建脚本兼容 `TAURI_SIGNING_PRIVATE_KEY_PATH` 并转为前者。值可以是私钥文件路径，无需在终端输出内容。
- 无口令密钥在非交互终端打包时设置 `$env:CI = 'true'`，避免 CLI 等待口令输入；有口令密钥应通过专用密码环境变量提供口令，不要写入仓库。
- 更新器的 `.sig` 签名不是 Windows Authenticode 代码签名；不能据此承诺没有 SmartScreen 提示。
- 计划要求的真实数据还原、安装版/便携版真机升级和桌面视觉检查尚未执行；未将这些项目算作自动化通过。
