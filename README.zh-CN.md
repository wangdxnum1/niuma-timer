# 🐎 牛马计时器

> 实时看看今天赚了多少钱，精确到秒——顺便看看这一天的班都怎么上的。
> [English](./README.md)
> 当前版本 **1.7.0**（2026-10-01）· [更新日志](./CHANGELOG.md)

一个轻量级 Windows 托盘常驻工具，给打工人用。它蹲在系统托盘里，实时显示：

- 今天**已经赚了多少**（¥）
- 已经**上了多少小时班**（小时/分钟/秒）
- **距下班还有多久**
- **赚钱速率**（¥/分）和**距发薪日天数**

托盘图标直接画出已赚金额——瞄一眼任务栏，就能感受到每秒入账的快感。

除了算工资，它还是一个**桌面行为看板**：加班、鼠标键盘活动、各应用使用时长、媒体播放时长全部在本地（SQLite）记录，并可在托盘里查看。

## 功能特性

- **只统计当天**——零点自动重置，不累计前一天
- **托盘图标画金额**——`¥328` 直接渲染在图标上，不用开窗口
- **多行 tooltip 对齐排版**——用全角空格对齐标签列，数值起点严格对齐（系统原生 tooltip）
- **托盘悬停彩色卡片**——可选，悬停时显示渐变金色数据卡片（设置里开关）；默认仍用系统原生 tooltip
- **时长格式可配置**——`hms`（几小时几分几秒）/ `hm`（几小时几分）/ `h`（小数小时）
- **单例模式**——第二次启动会聚焦已有窗口，而不是开新进程
- **开机自动启动**——设置里开关，底层使用官方 `tauri-plugin-autostart` 插件（Windows 即写入当前用户的 Run 注册表键，无需管理员权限）；注册表为唯一真相源，在任务管理器里手动禁用后设置页如实反映状态
- **双击托盘显示主窗口**——双击托盘图标打开设置界面
- **节假日自动获取**——从 CDN 拉取国务院放假安排（含调休补班），本地缓存；断网时用内置法定节假日表（2025/2026）兜底，未收录的年份才按周一到周五估算
- **无运行时依赖**——release 产物自包含（系统只需 WebView2 Runtime，Win10/11 一般自带）
- **加班追踪**——下班后锁屏离开，自动记录离开时刻并算加班费 + 饭补；支持按天查看/增/删/改
- **键鼠活动监控**——Raw Input（`WM_INPUT`）旁路采集键鼠，统计点击、滚轮、按键、移动，逐小时活跃桶 + 高频按键榜（输入法零延迟）
- **应用使用监控**——前台窗口钩子，按应用统计使用时长（白名单，如微信）
- **媒体播放监控**——音频会话峰值轮询，按软件统计播放时长
- **本地持久化**——所有历史（加班、活动、应用/媒体使用）存 WAL 模式 SQLite；配置与节假日缓存仍为 JSON
- **存储占用可视**——设置页显示总占用与九类细分（加班 / 键鼠活动 / 应用使用 / 媒体播放 / 索引与空闲页 / 写前日志 / 图标缓存 / 配置与节假日 / 运行日志），按占用降序；表级占用取 SQLite `dbstat` 精确值。可设保留期（默认永久保留）并一键整理，每天首次启动自动收缩写前日志
- **周账单**——侧栏新增「账单」tab，把一周的班、钱和摸鱼打成一张可翻页的账单；小票风 / 仪表盘风在设置里一键切换
- **摸鱼成本货币化**——主页实时显示「🐟 摸掉 ¥X · 摸鱼率 Y%」，与上方跳动的已赚金额形成「一边赚、一边烧」的对照，并按摸鱼率给四档损味文案
- **应用四分类**——应用使用按 工作 / 摸鱼 / 沟通 / 其他 归类，点标签即可改分类并即时重算全部历史
- **跨午夜加班归属**——通宵加班正确归属前一天（凌晨 06:00 前锁屏记前一天、时长 +24h），不再静默丢账
- **休息日 / 节假日加班**——接入国务院放假调休数据，休息日与法定节假日用独立起算时间与独立费率
- **历史回看 + CSV 导出**——加班明细翻月、活动 / 应用 / 媒体翻日回看任意历史；周账单与加班明细一键导出 CSV（带 BOM，Excel 双击中文不乱码）
- **存储占用细分与整理**——设置页九类细分（SQLite `dbstat` 精确值），可设保留期并一键整理收缩写前日志
- **远程会话识别**——RDP / 向日葵 / ToDesk / UU 远程被控期间不误记自动加班（可开关，手动补录不受影响）

- **月 / 年账单**——账单页支持「周 / 月 / 年」跨度切换，年度视图按月聚合；发薪日当天首次启动推送上月战绩通知（可关闭）
- **时间线回顾**——账单页洞察新增「时间线」tab：任选一天 24 小时逐行呈现前台四类构成（工作/摸鱼/沟通/其他）、该小时最常用应用、键鼠与媒体在响；日导航翻历史，无记录小时显示空行、不臆造「离开」
- **周报图片**——账单页一键把本期账单画成一张深底金字的报告卡（进账大数 / 四行明细 / 每日金条 / 最累最摸 / 损味金句），自动复制剪贴板并保存到下载目录
- **时薪计薪模式**——计薪方式支持「月薪 / 时薪」切换：时薪工、日结工直接按 时薪 × 工时 计薪，账单满勤与摸鱼成本折算全链路继承；月聘模式口径不变
- **专注时段统计**——洞察新增「专注」tab：工作类前台 + 键鼠活跃连续达标记一段（默认 25 分钟可调），每日段数 / 总时长 / 最长一段一目了然；睡眠空窗不计入，自上线起积累
- **应用分类智能建议**——归「其他」的应用给出一键分类建议（离线关键词规则），降低上手门槛
- **月报图片**——「存为图片」支持月跨度，金句措辞随期号切换
- **数据洞察三视图**——账单页另有三页：星期 × 小时的时段热力、近 8 期进账与摸鱼率趋势、周期键鼠劳损的身体账单
- **牛马守护提醒**——久坐提醒与下班提醒统一走 Windows 系统通知，全局快捷键 Alt+Shift+N 显隐窗口 / Alt+Shift+P 暂停监控；阈值可调，下班感知
- **手动暂停监控**——托盘菜单或 Alt+Shift+P 一键暂停全部监控，钱先冻结，恢复后不补记
- **六卡设置页**——薪资与作息 / 加班 / 守护 / 数据监控 / 外观 / 系统与数据，长说明统一收进折叠详情
- **自动更新**——启动 30 秒后与每 6 小时检查 GitHub Release，一键更新、可「跳过此版本」，升级后首次启动展示更新说明；绿色版下载新 exe 并校验 SHA-256 后退出替换，失败自动回滚
- **数据备份与一键还原**——一键把完整数据（库快照 + 配置 + 清单）打成单个 zip 存到「文档\niuma-timer-backup\」，列出全部备份并一键还原；还原经完整性校验、先自动保护性备份、重启后生效
- **启动日志带构建信息**——版本 / 编译时间 / git 提交 / 前端指纹编译期写入 exe，启动时落 `debug.log` 与 `panic.log`

## 计算原理

```
时薪 = 月薪 ÷ 当月实际工作日 ÷ 每日工时

今日已赚 = 已工作小时 × 时薪
赚钱速率（¥/分）= 时薪 ÷ 60
```

午休自动排除（上午段 + 下午段分别配置）。下班即封顶，非工作日显示"今天休息"。

加班通过 Windows 锁屏事件触发：在工作日、超过配置的加班起算时间后锁屏离开，即记录当日加班（原始时长 → 有效时长向下取 0.5h，加班费 = 有效时长 × 时薪，另有可选饭补）。

加班归属日由**锁屏时刻**决定：若离开时刻早于 06:00，视为熬过午夜，归属**前一天**并按 +24h 计时长——9/11 通宵到 9/12 01:30 锁屏，记在 9/11 共 7.5 小时，明细页显示为「次日 01:30」。

### 备份与还原

设置页「系统与数据」可把完整数据（数据库 + 配置 + 清单）打成单个 zip 存到「文档\niuma-timer-backup\」。库快照走 SQLite 的 `VACUUM INTO`——它会先合并 WAL 再产出页级一致的新库，直接拷在用的库文件会静默丢掉最近的写入。还原先校验备份（清单身份、`PRAGMA integrity_check`、七张业务表齐全），再为当前数据自动做一份保护性备份，然后铺好 `.pending` 文件并重启：文件交换发生在下一个进程取得单实例所有权后、打开数据库之前，因为应用整个生命周期持有同一个数据库连接，在活连接上换文件会把新旧页缓存混在一起。旧库留存为 `niuma.db.pre-restore.bak`；交换失败也绝不会阻止程序启动。

- **Windows 10 / 11**

## 构建

### 前置条件

- [Rust 工具链](https://rustup.rs)（stable，≥ 1.77）
- 项目基于 **Tauri v2**（Rust 后端 + 纯 HTML/CSS/JS 前端，无需 npm 打包）

### 一键编译（推荐）

```bat
build.bat            :: 同时构建 debug 和 release
build.bat debug      :: 仅 debug
build.bat release    :: 仅 release
```

产物输出到：

- `bin\debug\niuma-timer.exe`
- `bin\release\niuma-timer.exe`

脚本会自动探测 `rustc` 的 host triple，定位 `target\<triple>\<flavor>\` 下的产物。

### 手动编译

```bash
cd src-tauri
cargo build --release
# 产物：src-tauri/target/<triple>/release/niuma-timer.exe
```

### 打包发布（NSIS 安装包 / MSI / 便携版）

先安装 Tauri CLI（只需一次）：

```bash
cargo install tauri-cli --version "^2"
```

然后一条命令打包：

```bat
build.bat package
```

产物统一输出到 `bin\package\`：

| 产物 | 说明 |
|---|---|
| `*-setup.exe` | NSIS 安装向导（中文界面，默认当前用户安装，无需管理员权限） |
| `*.msi` | MSI 安装包，适合企业分发 / 静默安装 |
| `niuma-timer-1.0.0-portable.exe` | 便携版，双击即用，不安装、不写注册表 |

> 首次打包会自动下载 NSIS；打出 MSI 还需要 [WiX 3](https://wixtoolset.org/) 工具链。

### 一键发布（编译 + 打包 + 打 tag，发布由 CI 完成）

```bat
release.bat             使用 Cargo.toml 中的当前版本
release.bat 1.1.0       顺便把版本号改为 1.1.0（自动同步 Cargo.toml 与 tauri.conf.json）
release.bat 1.1.0 /y    全程不询问
```

本机按序执行：测试 → 编译 release → 打包三种产物 → 提交并打 tag → 推送。
**发布在云端完成**：推送 `vX.Y.Z` tag 会触发 `.github/workflows/release.yml`，在 GitHub
runner 上重新编译打包并创建 GitHub Release（进度见 Actions 页）。

- 本机预演打包仍需 `tauri-cli`，脚本检测到未安装会询问是否立即安装
- 一次性配置：把更新器签名私钥配到仓库 **Secrets** 的 `TAURI_SIGNING_PRIVATE_KEY`
  （可选 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`），缺失时发布任务会在更新器清单检查处失败
- 应急手动发布（CI 不可用时），复用 Git 凭据管理器里已有的 GitHub 令牌：
  `python scripts/publish_release.py --tag vX.Y.Z --version X.Y.Z --package bin/package`
- 版本号变更会改写 `Cargo.toml` 与 `tauri.conf.json`；若改写失败按提示用 `git checkout --` 还原

### 测试

跑 `build.bat test`（等价于 cargo test 加 `node scripts/run_all.js`）执行全部测试；前端断言脚本
经 `scripts/lib/fe_sources.js` 读取前端源码——它把 `frontend/js/` 下 10 个块按加载序拼接后再断言。
Rust 侧源码断言同理走 `scripts/lib/rs_sources.js`（main.rs 模块化后命令分布在 `cmds_*.rs`）。


## 使用方法

1. 运行 `niuma-timer.exe`——托盘出现图标（显示 `¥0`）。
2. **右键托盘 → 设置**：填写月薪、上午/下午上下班时间、发薪日，点「保存」。
3. 点「刷新工作日数据」拉取当年节假日，自动算出当月实际上班天数（也可手动覆盖）。
4. 托盘图标每秒刷新「今天已赚 ¥XX」。悬停查看信息；**双击托盘图标**打开主窗口——主界面展示实时工资，以及加班 / 活动 / 应用使用 / 媒体播放的概览，每个都有二级明细页。

### 配置项

| 字段 | 说明 |
|---|---|
| `monthly_salary` | 月薪（元） |
| `salary_mode` | 计薪方式：`monthly` 月薪（默认）/ `hourly` 时薪 |
| `hourly_wage` | 时薪（元/小时），salary_mode 为 `hourly` 时生效 |
| `focus_enabled` | 专注统计开关（默认开） |
| `focus_min_minutes` | 专注达标线（分钟，10–120，默认 25） |
| `am_start` / `am_end` | 上午上班/下班时间（如 `09:00` / `12:00`） |
| `pm_start` / `pm_end` | 下午上班/下班时间（如 `13:30` / `18:00`） |
| `payday` | 发薪日（每月几号，1–31） |
| `workdays_override` | 手动覆盖自动计算的上班天数（可选） |
| `duration_format` | 时长显示格式：`hms` / `hm` / `h`（默认 `hms`） |
| `tray_hover_card` | 用彩色悬停卡片替代系统原生 tooltip（默认关） |
| `overtime_enabled` | 启用加班追踪（默认关） |
| `overtime_start` | 加班起算时间 `HH:MM`（留空 = 下午下班时间） |
| `overtime_rate` | 加班费（元/小时，默认 20） |
| `overtime_meal_enabled` | 饭补开关（默认开） |
| `overtime_meal` | 饭补金额（元，默认 20） |
| `monitor_activity` | 鼠标键盘活动监控（默认开） |
| `monitor_app_usage` | 应用使用监控（默认开） |
| `monitor_audio` | 媒体播放监控（默认开） |

## 数据存放

- 配置文件：`%APPDATA%\niuma-timer\config.json`
- 节假日缓存：`%APPDATA%\niuma-timer\holiday_{年份}.json`
- 历史数据库：`%APPDATA%\niuma-timer\niuma.db`（SQLite，WAL 模式）
- 节假日数据源：[`NateScarlet/holiday-cn`](https://github.com/NateScarlet/holiday-cn)（经 jsDelivr CDN 分发，国务院放假安排，含调休补班）

## 技术栈

| 层 | 技术 |
|---|---|
| 后端 | Rust + Tauri v2 |
| 前端 | 原生 HTML / CSS / JS（无打包工具） |
| 单例模式 | `tauri-plugin-single-instance` |
| 托盘图标 | 运行时像素绘制，内置 5×7 点阵字体 |
| 持久化 | SQLite（`rusqlite`，WAL 模式） |
| Windows API | `windows` crate 0.61——WTS 锁屏事件、音频会话轮询、按 DPI 设置窗口图标、Raw Input（`WM_INPUT`）键鼠采集 |
| 节假日数据 | GitHub 托管 JSON 经 jsDelivr CDN，本地缓存 + 内置节假日表兜底 |

## 已知边界

- **休息日 / 节假日加班** 默认关闭，在设置中开启后才计入。休息日起算时间默认 09:00（休息日没有「下班时间」概念），费率可单独配置，未配置时逐级回退（法定节假日 → 休息日 → 工作日）。法定节假日与调休补班日的识别依赖节假日数据，该年份无数据时降级为按自然周几判断。
- 监控线程运行时会占用少量 CPU；不需要的功能可在设置中关闭，已统计数据不受影响。
- tooltip（原生模式）是系统渲染的纯文本（无颜色/图标），对齐依赖全角空格（U+3000）列宽计算。
- 不支持跨平台（macOS / Linux）。
